# The Life — 기획 논의 문서 (v0.1)

> 가장 너답게, 가장 특별한 삶을 경험하라

- **장르**: 스토리텔링 인생 게임 / 관전형 AI 게임
- **핵심 정체성**: 유저가 게임에 관여할 수 없는, 유저 중심의 게임
- **상태**: 방향 논의 단계. 이 문서는 확정 기획서가 아니라 결정을 위한 논의 자료다.

---

## 1. 컨셉 요약

유저는 시나리오를 정하고, 자신을 투영한 캐릭터를 만들고, 몇 가지 관심사를 정한다.
그 순간부터 캐릭터는 게임 속 세상에서 스스로 살아간다. 유저는 조작할 수 없다.
카카오톡을 열듯 앱을 열면, 캐릭터가 그동안 살아온 소식이 도착해 있을 뿐이다.

- 캐릭터는 유저의 존재를 모른다.
- 캐릭터는 수많은 역경을 겪지만, **반드시 목표한 바를 이룬다** (결말 보장).
- 유저는 '유령'으로서 제한적 개입만 가능하다 — 잃어버린 지갑에 돈을 채워주거나,
  은인을 보내 불탄 집을 고쳐주는 식. 이때 아이템(과금)을 사용한다.
- 다른 유저의 캐릭터와 게임 속에서 관계를 맺는다 — 애인, 친구, 같은 목표.

## 2. 왜 이 컨셉이 성립하는가

1. **관전의 재미는 이미 검증됨** — 방치형 게임, 관찰 예능, 브이로그, 다마고치.
   "내가 애착을 가진 존재가 살아가는 걸 지켜보는" 욕구는 보편적이다.
2. **LLM이 처음으로 이것을 가능하게 함** — 미리 짜인 분기가 아니라
   진짜 예측 불가능한 고유 서사. 3년 전엔 불가능했던 기획이 지금은 된다.
3. **"결말은 보장된다"는 정서적 안전장치** — 현실에서 지친 사람이
   안심하고 머무는 힐링 콘텐츠. SNS의 소란스러움에 대한 대안이라는
   포지셔닝과 일치한다.
4. **카톡형 UI** — 그래픽 비용 0, 텍스트 LLM의 강점과 일치,
   "무의식적으로 여는 앱"이라는 목표와 일치.
5. **유령 개입 = 자연스러운 수익모델** — 조작 불가 원칙을 깨지 않으면서
   (캐릭터는 유저를 모르므로) 과금 포인트가 서사 안에 녹아든다.

## 3. 코어 루프 (제안)

```
캐릭터 생성 ──▶ 캐릭터가 살아감 ──▶ 소식 도착 (하루 1~3회, 푸시)
                     ▲                      │
                     │                      ▼
              유령 개입(아이템) ◀── 유저가 읽고 궁금해함 ──▶ 내일 다시 열어봄
```

- **소식의 형태**: 캐릭터의 일기, 지인의 전언, 신문 기사, 사진 한 장 등.
  캐릭터가 유저에게 말하는 게 아니라, 유저가 몰래 엿보는 구조.
- **연속극 원칙**: 모든 소식은 작은 갈등이나 떡밥을 남기고 끝난다.
  조작이 없는 게임에서 리텐션의 유일한 원천은 "궁금함"이다.

## 4. 시스템 설계 스케치

이 게임의 진짜 엔진은 LLM이 아니라 **인생 상태 시뮬레이터**다.

```
[캐릭터 상태 DB]  ←  구조화된 진실의 원천
  - 프로필: 이름, 기질(성격), 시나리오, 인생 목표
  - 현재 상태: 위치, 직업, 재산, 건강, 감정
  - 관계 그래프: 인물별 친밀도·역사
  - 사건 로그: 지금까지 일어난 모든 일의 요약
  - 서사 아크: 목표까지의 큰 줄기 (기-승-전-결 어디쯤인가)

[사건 생성기]  ←  하루 1~3회 실행
  - 상태 + 아크 위치를 보고 "오늘 일어날 일"을 결정
  - 유령 개입(아이템)이 있으면 사건에 반영

[LLM 서사 레이어]
  - 결정된 사건을 캐릭터의 목소리로 "오늘의 소식"으로 집필
  - 집필 결과에서 상태 변화를 추출해 DB에 반영
```

이렇게 분리해야 하는 이유:
- **일관성** — LLM에게 매번 "오늘 이야기 써줘"라고만 하면 어제 만난 친구를
  잊고, 3개월치 인생이 서사로 이어지지 않는다. 기억은 DB가, 문장은 LLM이.
- **결말 보장** — 서사 아크를 시스템이 쥐고 있어야 "반드시 목표를 이룬다"를
  기술적으로 보장할 수 있다.
- **비용 통제** — 호출 횟수가 하루 1~3회로 고정되면 유저당 비용이 예측 가능하다.
  "하루 몇 번만 소식이 온다"는 제약은 오히려 기대감을 만든다.

## 5. 사주 연계 (기존 앱과의 시너지)

현재 리포지토리의 사주 분석 앱과 자연스럽게 이어진다:

- 캐릭터 생성 시 생년월일 입력 → 사주가 캐릭터의 **타고난 기질**과
  **운명의 흐름(대운·세운)**의 시드가 된다.
- "가장 너답게"라는 슬로건과 정확히 맞물린다 — 게임 속 나는 임의의 AI가
  아니라 내 사주를 타고난 나다.
- 사건 생성기가 세운(그 해의 운)을 참조해 사건의 색깔을 정할 수 있다.
  예: 재성운의 해 → 돈에 관련된 사건이 늘어난다.
- 기존 사주 앱 유저를 게임으로 데려오는 퍼널이 된다.

## 6. 소셜 레이어 (2단계)

- 게임 속에서 만나는 애인·친구가 실제로는 **다른 유저의 캐릭터**.
- 서로의 삶을 함께 볼 수 있고, 같은 목표를 정할 수 있다.
- 킬러 기능이지만 MVP에는 무겁다. 두 캐릭터의 서사를 동기화하는 문제
  (한쪽만 접속하는 경우, 서사 충돌)가 커서, 1인용 코어 루프 검증 후 착수.
- MVP에서는 NPC가 그 자리를 채우되, 데이터 구조(관계 그래프)는
  처음부터 유저 간 연결을 염두에 두고 설계한다.

## 7. 난제와 대응

| 난제 | 대응 |
|---|---|
| 서사 일관성 (LLM의 망각) | 상태 DB + 사건 로그 요약을 매 호출에 주입. LLM은 집필만 담당 |
| 리텐션 (조작이 없음) | 연속극 구조(떡밥), 푸시 알림, 하루 1~3회 도착의 희소성 |
| LLM 비용 | 호출 횟수 고정, 소식 길이 제한, 요약 캐싱 |
| 결말 보장 vs 뻔함 | 결말은 보장하되 경로는 예측 불가하게. "어떻게 이루는가"가 재미 |
| 유령 개입의 남용 | 개입은 사건에 '영향'만 주고 서사를 직접 쓰지 못함. 캐릭터는 끝까지 유저를 모름 |

## 8. MVP 제안 (1인용 코어 루프)

**검증할 가설**: "일주일간 지켜봤을 때, 계속 보고 싶은가?"

포함:
1. 캐릭터 생성 — 이름, 시나리오 선택(3~5종), 관심사, (선택) 생년월일→사주 기질
2. 하루 1~3회 소식 도착 — 카톡형 타임라인 UI
3. 서사 아크 — 2~4주 안에 하나의 목표가 이루어지는 시즌제
4. 유령 개입 — 아이템 2~3종만 (예: 지갑 채워주기, 은인 보내기)

제외 (2단계로):
- 유저 간 관계, 커플, 친구
- 결제 (아이템은 무료 재화로 검증)
- 네이티브 앱 (웹으로 검증)

## 9. 결정이 필요한 질문 (열림)

1. **첫 결과물** — 플레이 가능한 프로토타입 먼저? 기획서(GDD) 먼저? 병행?
   → *추천: 프로토타입 먼저. 만들면서 기획이 구체화된다.*
2. **사주 연계** — 필수 요소로? 선택 옵션으로? 완전 독립?
   → *추천: 선택 옵션으로 시작하되, 이 게임의 차별점으로 키운다.*
3. **시간 구조** — 실시간 동기(캐릭터도 현실처럼 하루를 삶)? 압축 시간
   (현실 하루 = 게임 한 달)? 접속 시에만 진행?
   → *추천: 실시간 동기. 애착과 기대감, 비용 통제 모두에 유리.*
4. **프로토타입 플랫폼** — 카톡형 UI 웹앱? 기존 Streamlit 확장? 모바일 앱?
   → *추천: 모바일 브라우저용 카톡형 웹앱. 최종 형태에 가까운 경험으로 검증.*
