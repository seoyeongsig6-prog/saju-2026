# The Life — 게임개발 계획서 (v1.1)

> 가장 너답게, 가장 특별한 삶을 경험하라

| 항목 | 내용 |
|---|---|
| 게임명 | The Life (가칭) |
| 장르 | 스토리텔링 인생 게임 / 관전형 AI 게임 |
| 플랫폼 | 모바일 웹(PWA)으로 검증 → **Android/iOS 네이티브 앱 출시가 최종 목표** |
| 핵심 한 줄 | 내가 살고 싶은 삶을 아바타가 대신 살고, 나는 그 삶을 지켜본다 |
| BM | 행운 패키지(개입·예감) + 관전 상품 + 광고 — **수익 창출이 명시적 목표** |
| 동시 관전 | 유저는 여러 삶을 동시에 지켜볼 수 있다 (기본 슬롯 2개 이상, 추가 슬롯 판매) |
| 저장 | 삶의 기록은 영구 보존 (외부 DB) — 나온 글은 언제든 다시 읽을 수 있다 |
| 문서 상태 | v1.1 — 기획 뼈대 확정 + 갈등 은행 DB화·커뮤니티 설계 추가 |

---

## 1. 게임 컨셉

### 1.1 철학

여행을 가고 싶지만 늘 바쁘고, 합격하고 싶지만 번번이 떨어진다.
대부분의 인생은 바라는 것을 쉽게 내어주지 않는다. The Life는 그 바람이
이루어지는 세상이다. 유저는 살아보고 싶은 삶을 고르고, 아바타가 그 삶을
대신 산다. 유저는 개입할 수 없다 — 딱 세 번을 제외하고는.

### 1.2 핵심 규칙 (게임의 본질)

1. **조작 불가.** 유저는 아바타의 삶을 지켜볼 수만 있다.
2. **아바타는 유저의 존재를 모른다.** 영원히.
3. **아바타는 스스로의 힘으로 난관을 극복한다.** 이것이 서사의 핵심이며,
   그 과정에서 그 인생의 개성이 나온다. 육성·돌봄 게임이 아니다.
4. **전투는 질 수 있다. 그러나 시즌 목표는 결국 이루어진다.**
   꼭 필요한 거북선이 없으면 그 해전은 진다 — 동료를 잃고 길이 험해질
   뿐, 이야기의 문은 닫히지 않는다.
5. **목표 달성 시점은 아무도 모른다.** 3일일 수도, 한 달일 수도 있다.
6. **개입은 시즌당 딱 3번.** 돈이 아무리 많아도 3번. 횟수는 살 수 없고
   크기만 살 수 있다.
7. **시간은 현실과 동일하게 흐른다.** 이순신의 하루도 24시간이다.

### 1.3 차별점

- LLM 기반의 진짜 예측 불가능한 고유 서사 (미리 짜인 분기 없음)
- 그래픽 없는 텍스트 스트리밍 — "무의식적으로 여는 앱", SNS의 소란에
  지친 사람들을 위한 힐링 콘텐츠
- 시즌이 끝나면 한 편의 완결된 전기(傳記)가 남는다 — 소장·공유 가치
- 개입 3회 제한이 만드는 희소한 결정의 무게

## 2. 타겟 유저

- 복잡한 게임과 긴 문장이 부담스럽지만 스마트폰을 손에서 놓지 않는 사람
- SNS 피로감을 느끼는 사람 (나만 빼고 다 행복해 보이는 피드의 대안)
- 대리만족·힐링 콘텐츠 소비층, 웹소설·관찰예능 시청층
- 1차 시장: 한국어 / 국내 모바일

## 3. 핵심 시스템

### 3.1 아바타 생성

- **방식 1 — 실존 인물 검색** (역사 인물): 실제 생애가 세계와 갈등의
  재료. 이순신, 스티브 잡스 등. 시대 고증이 세계의 질감을 만든다.
- **방식 2 — 커스텀 아바타** (가상의 나): 나이·성격·직업/시나리오·
  시대와 장소·**인생 목표**를 정한다.
- **생존 유명인 차단** (퍼블리시티권·명예훼손 리스크. 추후 라이선스
  제휴로 개별 개방 가능). 차단 문구:

  > **그의 삶은 아직 진행 중입니다.**
  > 지금 이 순간에도 현실에서 살아가고 있는 사람의 삶은
  > The Life가 대신 지어낼 수 없어요.
  > 그의 이야기가 완결되면, 언젠가 이곳에서 만날 수 있을 거예요.

### 3.2 살아있는 세계 — 일과표 방식

유저가 새벽 3시에 들어가도 아바타의 삶이 보여야 한다. 단, 24시간
서사를 생성하면 비용이 무한대이므로:

```
[매일 자정]   일과표 생성 (LLM 호출 1회)
              상태·직업·계절·진행 중 사건 기반, 시간대별 하루 일과
[유저 접속 시] 현재 시각 → 일과표에서 "지금 하는 일" 도출
              → 현재 진행형 장면 즉석 집필 (스트리밍)
              → 마지막 방문 이후 "그동안" 요약 생성
[하루 1~3회]  사건 비트 — 갈등 엔진이 예약한 주요 사건, 푸시 발송
```

- 미접속 시에도 일과표·사건 로그는 쌓인다 → 세계는 실제로 계속
  굴러간 것. 비용은 접속 시에만 발생 → 유저당 비용 예측 가능.
- 새벽엔 자고 있다. 그것도 살아있음의 증거다.

### 3.3 보는 방식 — 3층 구조

| 층 | 이름 | 내용 |
|---|---|---|
| A | **지금** (홈) | 현재 진행형 라이브 장면. 대화가 몇 초 간격으로 한 줄씩 올라오는 스트리밍. 훔쳐보는 느낌 |
| B | **그동안** (피드) | 마지막 방문 이후의 일들. 큰 사건은 카드, 일상은 한 줄. 일기·전언·소문·기사 형식 |
| C | **이야기** (아카이브) | 에피소드 기록. 시즌 종료 시 완결된 전기가 된다 |

배치: 열면 A, 위로 스크롤하면 B, 메뉴에서 C.

### 3.4 서사 엔진

이 게임의 진짜 엔진은 LLM이 아니라 **인생 상태 시뮬레이터**다.
기억은 DB가, 문장은 LLM이 담당한다.

```
[아바타 상태 DB]   프로필 / 현재 상태(위치·재산·건강·감정) /
                   관계 그래프(고정 캐스트) / 사건 로그 / 서사 아크 위치
[갈등 엔진]        갈등 은행(실제 생애의 갈등 + 생성 갈등) / 3막 페이싱 /
                   숨겨진 마일스톤 / 달성 시점은 창발적(예측 불가)
[LLM 서사 레이어]  사건·일과를 세계 질감으로 집필 → 상태 변화를 DB에 반영
```

- **세계 텍스처**: 시나리오별 어휘, 하루의 리듬, 돈의 단위, 고정
  캐스트, 행운 사전. 어부의 세계라면 물때·경매·그물 손질·뱃사람의
  말투. 디테일한 리얼리티는 여기서 나온다.
- **고정 캐스트**: 김 선장이 매번 나와야 유저가 그 세계에 정든다.
- **연속극 원칙**: 모든 사건 비트는 다음이 궁금하게 끝난다. 조작 없는
  게임에서 리텐션의 유일한 원천은 궁금함이다.
- **극복의 주체는 언제나 아바타**: 갈등 엔진의 기본값은 아바타가
  자신의 성격·능력·관계로 난관을 푸는 것. 개입 없이도 서사는
  완결된다 — 다만 더 험할 뿐.

**갈등 생성 — 즉흥 발제 + 구조화 저장 [v1.2 확정]**

갈등은 미리 만들어두지 않는다. 갈등이 필요해지는 순간, LLM이 그 삶의
지금 상황(세계·최근 사건·아크 위치·고정 캐스트)을 보고 갈등 하나를
즉흥으로 발제한다 — LLM이 이미 아는 지식(실존 인물의 실제 생애 등)이
그대로 재료가 된다. 발제된 갈등은 아래 카드 구조로 DB에 저장되어
이후 며칠간 그 구조대로 전개된다. **즉흥이 다양성을, 구조가 연속성
(연속극 긴장·결말 보장·페이싱)을 담당한다.**

갈등 은행(수제 검수 카드)은 폴백이자 품질 하한선으로 유지한다:
LLM 실패 시, 그리고 잘 먹힌 즉흥 갈등을 검수해 은행에 승격시키는
파이프라인(→ 자라는 콘텐츠 자산)으로.

갈등 카드 스키마:

| 필드 | 내용 |
|---|---|
| 유형 | 재정 / 관계 / 신체·건강 / 자연 / 권력·사회 / 내면 |
| 규모 | 소(일상) / 중(며칠짜리) / 대(시즌의 큰 산) |
| 발동 조건 | 상태 DB 조건식 (예: 어획량 좋음 + 정박 중 + 2막 이후) |
| 전개 단계 | 씨앗 → 고조 → 절정 → 해소 (며칠에 걸친 서사 단위) |
| 해소 경로 | 아바타의 성격·능력·관계에 따라 분기 |
| 행운 훅 | 개입이 닿으면 해소 경로가 어떻게 바뀌는가 (번역 시스템 연결점) |
| 결과 | 상태·관계·감정 변화, 흉터 또는 성장 기록 |

- **출처 2종**: ① 실존 인물의 실제 생애 갈등 (아크 위치에 앵커됨)
  ② 세계 텍스처 기반 생성 갈등 (LLM 대량 생성 → 사람 검수 → 입고)
- **재사용과 변주**: 카드 뼈대는 유저 간 공유하되, 집필 시 그 아바타의
  성격·관계·디테일로 변주된다 → 콘텐츠 비용을 시나리오 단위로 통제.
- **점진적 DB화 [확정]**: 프로토타입은 시나리오당 카드 20~30장의
  파일 기반(YAML/JSON)으로 시작 → 운영 DB 테이블로 이관.
  사용 기록(어떤 유저에게 언제 썼는지 — 중복 방지), 성과 지표
  (해당 카드 전개 중 접속률·완주율)를 축적해 카드 품질을 데이터로
  관리한다. 잘 먹히는 갈등은 남고, 반응 없는 갈등은 도태되는
  **자라는 콘텐츠 자산**이 된다.
- 예측 불가성의 출처: 어떤 카드가 몇 개, 얼마나 길게 전개되는지가
  확률적이므로 같은 시나리오도 3일에 끝나거나 한 달을 끈다.

### 3.5 시즌 구조

- 목표 달성 = 시즌 종료 → **전기 생성** → 유저에게 묻는다:
  "이 아바타로 다음 목표를 이어갈까요, 새로운 삶을 시작할까요?"
- 시즌 2는 상태·관계가 이어진다 (쌓인 세계가 자산이 된다).

### 3.6 개입 시스템 — 행운 게이지 [확정]

```
[모은다]  보상형 광고 시청(하루 제한, 소량) / 결제 패키지(대량)
          → 행운 게이지에 쌓인다. 시즌 이월 가능.
[쓴다]    개입 기회(시즌 3개) 중 하나를 열고, 실을 행운의 양을 정한다.
          소: 잃어버린 지갑 채우기 / 중: 은인, 기회 / 대: 거북선 한 척
[번역]    행운은 절대 날것으로 도착하지 않는다.
```

**번역 시스템** — "돈이 하늘에서 떨어지는" 일은 없다. 갈등 엔진이
그 세계의 인과로 번역해 배달한다:

1. **기존 캐스트를 쓴다.** 은인은 낯선 사람이 아니라 관계 그래프에
   이미 있는 인물 (김 선장이 보증을 서준다). 개입이 관계를 깊게 만든다.
2. **행운 사전.** 그 세계에서 행운이 나타나는 그럴듯한 형태 목록.
   조선 수군: 날씨·조류·조정의 결정·기술자의 진척. 현대: 우연한
   재회·입소문·계약 성사.
3. **아바타가 행운을 해석한다.** "하늘이 돕는구나", "돌아가신 어머니가
   지켜주시는 것만 같다." 아바타는 모르고, 유저만 안다.
   **개입의 진짜 상품은 물자가 아니라 이 장면이다.**

**설계 의도**: 3회 제한 때문에 개입은 소비가 아니라 결정이 된다 —
"지금 쓸까, 더 큰 위기를 위해 아껴둘까." 그리고 마지막 남은 한 번엔
크게 쓰고 싶어진다. 상한이 지불 의사를 만든다.

### 3.7 커뮤니티 — 서사 공유·관전·랭킹 (Phase 2)

내 아바타의 서사를 커뮤니티에 올리고, 다른 유저가 관전한다.
**자주가 아니라 굵직굵직하게** — 피드를 채우는 SNS가 아니라,
좋은 이야기만 올라오는 조용한 게시판.

- **하이라이트 게시**: 올릴 수 있는 것은 굵직한 순간뿐이다 —
  큰 갈등의 절정과 해소, 개입(행운)의 순간, 그리고 시즌 완결 전기.
  시스템이 하이라이트 후보를 추천하고, 유저가 골라서 게시한다.
  일상 잡담·짧은 글 게시는 아예 불가능하게 설계 (소란 원천 차단).
- **게시판 구분: [현실] / [역사]**
  - **현실**: 커스텀 아바타의 삶 (어부, 자영업자, 목수…)
  - **역사**: 실존 인물의 삶. 이 보드의 묘미는 **같은 인물, 다른 삶** —
    유저 천 명의 이순신은 천 개의 명량을 치른다. 같은 인물을 산
    서사끼리 자연스럽게 비교·경쟁이 생긴다.
- **반응은 좋아요와 배지만. 댓글은 없다.**
  - 좋아요: 무료, 무제한. / 배지: 유료 특별 반응 (감동·존경·눈물…),
    전기에 영구히 새겨진다 (별풍선 모델, §4.1).
  - 댓글을 두지 않는 이유: "SNS의 소란에 지친 사람들의 대안"이라는
    정체성 유지 + 악플·중재 비용 원천 제거. 응원은 말 없이.
- **랭킹**: 주간 인기 서사 (좋아요 기준, 현실/역사 각각) +
  **명작 전당** (완결 전기 대상, 시즌 단위). 랭킹은 아바타와 그
  삶에 대한 것이지 유저 계정 과시가 아니다 — 표기도 아바타 이름 중심.
- **관전과 구독**: 하이라이트가 좋았다면 그 아바타를 '구독' —
  이후 그 아바타의 굵직한 순간이 내 관전 탭에 도착한다.
  (2단계 라이브 관전·유저 간 관계의 진입로가 된다)
- **밸런스 유의점**: 게시는 유저의 선택 (기본 비공개). 커스텀
  아바타의 이름·시나리오에 대한 최소한의 신고·검수 장치 필요.

## 4. 수익 모델

### 4.1 수익원

| 수익원 | 내용 | 비고 |
|---|---|---|
| **행운 패키지** | 개입에 실을 행운 (결제) | 매출 중심축. 횟수가 아닌 크기를 판다 |
| **보상형 광고** | 시청 → 행운 소량 적립 | 무과금 유저의 참여 경로 |
| **시즌 패키지** | 시즌 시작 시 1회: 광고 제거 + 소식 늘리기 + 자세히 보기 + 전기 고급판 | 시즌이 유한하니 구매도 시즌 단위 |
| **관전 상품 (단품)** | 아래 표 | 서사 영향 없음 → P2W 불가 구조 |
| **전기 소장** | 디지털 기본판 무료, 고급 판형·삽화·인쇄본 유료 | 감정적 소장 가치 |
| **배지** (2단계) | 공유된 전기에 남기는 특별 배지 | 별풍선 모델 |

### 4.2 관전 상품

| 상품명 | 내용 |
|---|---|
| 소식 늘리기 | 하루 소식 3회 → 5회 |
| 자세히 보기 | 장면이 더 길고 디테일하게 |
| 꿈 보기 | 아바타의 꿈·속마음을 하루 1회 |
| 다른 시점 보기 | 다른 인물의 눈으로 본 장면 |
| 장면 그림 | 명장면 일러스트 1장 |
| 아바타 추가 | 슬롯 +1, 여러 삶 동시 관전 |
| 광고 제거 | — |

### 4.3 가드레일 (하지 않을 것)

- 개입하지 않았다고 아바타를 벌주지 않는다. 위기는 서사가 만든다.
- 결제 독촉 푸시 금지. 푸시는 소식이지 독촉이 아니다.
- 위기 예고는 서사 안에서만 (척후병의 보고, 흉흉한 소문).
- 아바타는 유저에게 도움을 요청할 수 없다 — 유저의 존재를 모르니까.
- '매일 돌보기'류 상시 개입 장치를 두지 않는다. 개입은 시즌 3회의
  큰 결정뿐이다.

## 5. 기술 설계

### 5.1 스택 (제안)

| 레이어 | 선택 | 이유 |
|---|---|---|
| 프론트 | React + Vite, PWA | 카톡형 채팅 UI·스트리밍 표현·웹푸시. 모바일 브라우저 우선 |
| 백엔드 | Python (FastAPI) | 기존 Python 경험 활용, LLM 연동 용이 |
| DB | 프로토: SQLite → 운영: PostgreSQL | 상태 DB·사건 로그·관계 그래프 |
| 스케줄러 | APScheduler / cron | 자정 일과표, 사건 비트 예약 |
| LLM | 공급자 교체 가능한 추상화 레이어 | 집필(고품질 모델)과 요약·일과표(저비용 모델) 분리 |
| 푸시 | Web Push API | PWA 알림 |

### 5.2 데이터 모델 (개요)

```
User        — 계정, 행운 게이지, 보유 상품
Avatar      — 프로필, 기질, 시나리오, 인생 목표, 현재 상태
Season      — 목표, 아크 위치, 숨겨진 마일스톤, 개입 잔여 횟수(3)
Cast        — 고정 등장인물, 아바타와의 관계 상태
EventLog    — 모든 사건 기록 (요약본이 LLM 컨텍스트가 됨)
DaySchedule — 일과표 (날짜별)
Intervention— 개입 기록 (크기, 번역된 사건)
Biography   — 시즌 종료 시 생성된 전기
ConflictCard— 갈등 카드 (은행). 사용 기록·성과 지표 포함
Highlight   — 커뮤니티 게시물 (하이라이트), 좋아요·배지 집계
```

### 5.3 LLM 비용 구조

유저 1인 1일 기준 호출: 일과표 1회(저비용 모델) + 접속 장면 1~3회 +
사건 비트 1~3회 + 요약 갱신. 소식 빈도가 상한을 정하므로 비용은 선형적
예측 가능. 프로토타입 단계에서 실측 후 상품 가격을 역산한다.

## 6. 개발 로드맵

### Phase 0 — 프로토타입 (목표: 4~6주)

**검증 가설: "일주일간 지켜봤을 때, 계속 보고 싶은가?"**

1. 아바타 생성 — 커스텀 + 역사 인물 3인 (예: 이순신, 조선 어부,
   현대 자영업자), 생존 유명인 차단 문구
2. 일과표 시스템 + 스트리밍 "지금" 화면 + "그동안" 피드
3. 갈등 엔진 v1 — 갈등 은행, 3막 페이싱, 창발적 달성 시점
4. 하루 1~3회 사건 비트 + 웹푸시
5. 개입 3회 + 행운 게이지 + 번역 시스템 (광고·결제는 목업, 무료 지급)
6. 시즌 종료 → 전기 생성 → "이어갈까, 새로 시작할까"

### Phase 1 — 클로즈드 베타

- 실제 광고 SDK·결제 연동, 상품 가격 확정
- 관전 상품 1차 (소식 늘리기, 자세히 보기, 꿈 보기)
- 시나리오·역사 인물 확충, 세계 텍스처 팩 파이프라인화
- 지표: D1/D7 리텐션, 일 접속 횟수, 시즌 완주율, 개입 사용 패턴

### Phase 2 — 커뮤니티 & 확장

- 커뮤니티 (§3.7): 하이라이트 게시, [현실]/[역사] 게시판, 좋아요·배지,
  주간 랭킹 + 명작 전당, 아바타 구독
- 라이브 관전 공개 (친구가 함께 지켜보기)
- 유저 간 관계 — 게임 속 애인·친구가 다른 유저의 아바타 (킬러 기능)
- 갈등 은행 운영 DB 이관 + 성과 지표 기반 카드 관리
- 네이티브 앱, 다국어, 생존 유명인 라이선스 제휴

## 7. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 서사 일관성 붕괴 (LLM 망각) | 상태 DB + 사건 로그 요약 주입. LLM은 집필만 |
| 리텐션 (조작 없는 게임) | 연속극 원칙, 푸시, 하루 1~3회 도착의 희소성 |
| LLM 비용 | 호출 상한 고정, 모델 이원화, 프로토 실측 후 가격 역산 |
| 결말 보장 vs 뻔함 | 결말은 보장, 경로는 예측 불가. "어떻게"가 재미 |
| P2W 반감 | 개입 횟수는 판매 불가(3회 고정), 관전 상품은 서사 무영향 |
| 실존 인물 법적 리스크 | 생존 유명인 차단, 역사 인물 중심, 제휴로만 개방 |
| 다크패턴 논란 | §4.3 가드레일 준수 |
